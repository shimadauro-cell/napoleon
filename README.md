# くるくる温泉ナポレオン部

5人で遊ぶトランプ「ナポレオン」のブラウザゲーム。人間1人＋CPU4人。インストール・ビルド不要。

## 遊ぶ

`index.html` をブラウザで開く（ダブルクリック）。GitHub Pages に置いても同じファイルで動きます。
ローカルサーバーで開きたい場合は `tools/serve.ps1` を実行して http://localhost:8124/ を開きます（任意）。

| モード | 内容 |
|---|---|
| チュートリアル | 7レッスン＋練習1局。固定配札で2〜3回操作して確認。中断・再受講可。戦績に入らない |
| 1局遊ぶ | 配札から10巡まで。結果に得点表のポイントを表示 |
| 5局マッチ | 5局の合計ポイントで順位（同点は同率）。配り直しは局数に数えない |
| 観戦 | CPU 5人。「全手札を公開」は画面だけの機能で、CPUの判断は通常と同じ観測情報だけ |

- ルールは **ぐるぐる温泉準拠** のみ（簡略ルール・カスタム設定はなし）。プレイ画面にはルール名を出さず、遊び方の画面に表記。
- 1局・5局マッチでは、自分のキャラを5人（ユウ・クロウ・ミラ・レン・ルナ）から選べます。残りの4人がCPU。
- CPUの強さ：やさしい／標準。
- 右上：ヒント（H）、BGM、SE、演出速度×1〜×3、ログ（L）、遊び方、メニュー。
- 操作：札を選ぶ→「出す」（Enter／同じ札をもう一度クリック）。Escで選択解除、←→で札の移動。出せない札は暗く表示され、押すと理由が出ます。
- 設定（保存される）：BGM／SE、演出速度、動きを減らす、ヒントの初期値、巡ごとに止める、戦績の消去。
- 言語：タイトル画面右上の「日本語 / English」で切り替え（ページを読み直して反映。ゲーム中は切り替えない。選んだ言語は保存）。
- URL オプション：`?lang=en` / `?lang=ja`（その回だけ言語を指定）、`?seed=123`（配札とCPUの判断を再現）、`?demo`（起動時に観戦）。

## 採用ルール（NAPOLEON_SPEC.md v0.3）

ニコニコ大百科「ナポレオン（トランプ）」の記事画像（ぐるぐる温泉を基にした説明）に準拠。公式の完全再現とは表示しません。

- 53枚（ジョーカー1枚）、5人に10枚ずつ、交換札3枚。得点札はA/K/Q/J/10の20枚。
- 競り：前局ナポレオンから時計回り。初局の開始席はシード乱数（補完）。強さは枚数→♠＞♥＞♦＞♣。宣言者以外の4人が続けてパスで確定、♠20は即確定。全員パスは配り直し（開始席は維持、局数・ポイントは不変）。最低宣言は標準13枚。
- 副官：ナポレオンが53枚のどれかを指定。持ち主が副官（拒否不可）。自分の手札・交換札にあれば単独戦。指定札が場に出るまで本人以外に正体を出さない。
- 交換：13枚から3枚捨てる。得点札は表向きで公開、非得点札は裏向き（回収後も非公開）。捨て札は**最初の巡の勝者**が取得。
- 札出し：同じマークがあれば必ず出す（ジョーカーは例外）。マイティ・正J・裏Jも印刷されたマークで判定。先手ジョーカーは要求マークを4つから自由に指定。先手の♣3は**ジョーカー請求**（持っている人は♣があってもジョーカー必須）。
- 強さ：よろめき（♠A＋♥Qで♥Q）＞マイティ＞ジョーカー（先手・後続同じ）＞正J＞裏J＞セイム2（2巡目から）＞切札＞台札マーク。
- 得点表（記事の表をそのまま。1局1行だけ適用）：通常勝利 +4/+2/0、連合軍勝利 0/0/+2、単独勝利 +6、20枚 +6/+4、単独20枚 +10、単独戦の連合軍勝利 各+1。

## ファイル構成

```
index.html / css/style.css  画面（基準1920×1080を拡縮。小さい横画面では手札・操作を大きくする compact 表示）
js/i18n.js       言語（日本語 / 英語）。画面の文字は NP.L('日本語', 'English') の対で持つ
js/engine.js     ルール：配札・競り・合法手・勝者判定・状態遷移・得点。DOM・タイマー・音・保存に依存しない
js/ai.js         CPU。getObservation(state, seat) の戻り値だけで判断
js/advisor.js    ヒント。CPUと同じ観測情報だけで、おすすめと理由を出す
js/ui.js         描画・入力・ログ・結果・設定・戦績・画面遷移
js/tutorial.js   レッスンの台本（固定配札）と進行。DOMなしの台本検証 simulate() も含む
js/demo.js       観戦
js/audio.js      BGM（132BPM・Cメジャーの明るいポップ。ヨナ抜き音階のマリンバ、終盤は鉄琴が加わる）・効果音（Web Audioで合成。最初の操作後に再生）
js/fx.js         演出（役札を出した時／役で勝った時のカットイン、大きな文字、紙吹雪。「動きを減らす」で揺れ・フラッシュ停止）
js/art.js        仮SVG（キャラ5人＋マスコット、露天風呂の背景）と差し替え画像の自動読み込み
js/tests.js      ルールテスト本体（tests.html と tests/run.js で共通）
tests.html       ブラウザでルールテスト＋チュートリアル台本検証
tests/run.js     ルールテスト（Node）
tests/tutorial.js チュートリアルの勝者・勝因の一致（Node）
tests/sim.js     CPU対CPUのシミュレーション（Node）
tests/regression.js 不具合の再現テスト（Node。ヒントの台札マーク判定など）
tools/serve.ps1  任意のローカルサーバー
assets/chars/    差し替え画像（ART_SPEC.md）
```

エンジンAPI：`createGame(config, seed)`、`getObservation(state, seat)`、`getLegalActions(state, seat)`、`applyAction(state, action)`、`resolveTrick(cards, context)`（`winnerSeat`・`reasonCode`・`pointCardCount`）。
状態遷移：DEAL→BIDDING→CALL_ADJUTANT→EXCHANGE→PLAY→TRICK_RESULT→…→ROUND_RESULT→MATCH_RESULT（全員パスは REDEAL_WAIT）。
合法手（`legalPlays`）と強さ（`resolveTrick`）は別関数。エンジンは手番・所持札・フェーズ・操作IDを再検証します。
乱数は配札（`seed|deal`）と判断（観測情報から作る key）で独立し、音や演出では消費しません。

### 画面での確認（ブラウザのプレビューで実施）

- 1920×1080相当（1281×720表示）：タイトル→モード選択→競り→副官指定→交換→10巡→結果→巡の振り返り。
- 844×390（スマホ横向き相当）：compact 表示で手札・操作ボタン・ヒントが重ならないこと。
- チュートリアル（レッスン6：マイティ、♣3のジョーカー請求）、観戦（全手札公開）。
- 札の連打＋Enter連打で1枚しか出ないこと、CPUの手番中にタイトルへ戻ってもタイマーが残らないこと、エラーなし。

### 未実施・既知の制約

- `file://` での直接起動はプレビュー環境では開けないため未確認（外部fetch・ES Modules を使わない構成なので動く想定）。実機スマートフォンでの確認も未実施。
- 標準CPUは見えない札を個別にサンプリングせず、公開情報（出た札・切れたマーク・手札枚数）から「上回られる確率」を見積もる方式。秘密情報は使いません。
- 途中局の保存・復元はなし（仕様どおり初版では不要）。
- 画像は仮SVG。差し替えは ART_SPEC.md。

## 素材の差し替え

`assets/chars/<キャラID>/avatar.webp`（必須）、`cutin.webp`、`cutin_ok.webp`、`cutin_ng.webp` を置いて再読み込み。
WebP → PNG → 仮SVG の順で自動選択します。規格は `ART_SPEC.md`。
背景は `assets/bg/onsen.webp`（または `.png`、1920×1080）を置くと、仮SVGの露天風呂の代わりに使います（テーブルはそのまま上に重なります）。
